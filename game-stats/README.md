# Рубилово — статистика игр

Источник данных — приватный Google Docs «Рубилово». `games.csv` — публичная структурированная копия, `index.html` — общий дашборд, а `chess.html` — отдельный дашборд обычных шахмат. Для шашек используется отдельный режим `index.html?view=checkers`, который не требует изменения GitHub Actions. Исходный документ не публикуется и не изменяется при обновлении статистики. При ручном обновлении ChatGPT сверяет всю историю и предлагает изменения в GitHub. Для обычных последующих обновлений действует отдельное правило проекта.

## Открыть дашборд

Общий дашборд: https://illia-yehorov.github.io/public-personal-lab/game-stats/

Шахматный дашборд (только обычные шахматы): https://illia-yehorov.github.io/public-personal-lab/game-stats/chess.html

Дашборд шашек: https://illia-yehorov.github.io/public-personal-lab/game-stats/?view=checkers

При HTTP(S) страница автоматически загружает соседний `games.csv` и пересчитывает показатели и фильтры. На общей странице находятся две компактные сводки **обычных шахмат** и две сводки **шашек** (счёт и контроли времени), каждая со ссылкой на профильный раздел. Сводки на общей странице независимы от общих фильтров; в профильных разделах сводки, временные диаграммы и история учитывают локальные фильтры. Дашборд шашек отображается из `index.html` через параметр `?view=checkers`, поэтому для его публикации не требуется добавлять файл в `.github/workflows/deploy.yml`. В этом режиме показываются только шашки, включая прорыв, поддавки, классические, русские и международные варианты. В шахматных сводках и отдельной шахматной странице **исключён `chess/three_check`**; эти исторические партии **остаются в `games.csv`**, в общих показателях, разделе по видам игр, временных рядах и записях общего дашборда. Фильтры по умолчанию свёрнуты в блок `<details>` и при настройке показывают число активных условий. В строке статуса видно дату последней партии из CSV, **время последнего изменения `games.csv` в Git (`Europe/Kyiv`)** и время загрузки файла браузером. Первое и второе — разные даты: новое открытие страницы не означает обновление статистики. Для автоматической загрузки GitHub Actions встраивает время последнего commit для `games.csv` в публикуемые HTML во время деплоя; локально и при ручной загрузке CSV показываются дата последней партии и время загрузки, но время Git-обновления не приписывается вручную выбранному файлу. При локальном открытии `index.html` через `file://` нажми **«Загрузить CSV»** и выбери находящийся рядом `games.csv`. База данных, backend и сторонние JavaScript-библиотеки не нужны. Дашборд не редактирует CSV.

## Периоды и количество побед

Один переключатель **7 дней / 14 дней / Всё время** работает на общем дашборде, в шашках и в обычных шахматах. Он изменяет всю статистику, таблицы и график. Интервалы включают текущий день по часовому поясу Europe/Kyiv. Для 7 и 14 дней столбцы графика группируются по дням, для всей истории — по календарным неделям (понедельник — воскресенье).

На графике показано **абсолютное количество партий**, а не проценты или разница между игроками. Для каждого дня или недели отображаются три соседних столбца: **зелёный** — победы Лёхи, **оранжевый** — победы папы, **серый** — ничьи. Вертикальная ось измеряется количеством партий (целые числа). Например, счёт 10:5 рисуется как два столбца высотой 10 и 5; счёт 10:10 — два одинаковых ненулевых столбца, а отсутствие игр — пустой день с n=0. Под каждой датой **n** — сумма всех партий, включая ничьи. Нулевые результаты не рисуются, так что график не показывает фиктивные столбцы. При наведении или фокусе на столбце видно точный счёт за период; над каждым ненулевым столбцом указано количество партий. Длинная история прокручивается горизонтально; при отсутствии партий в выбранном периоде показывается сообщение.

Короткие периоды пересекаются с ручными фильтрами «С даты» и «По дату», а также со всеми остальными фильтрами. Кнопка «Сбросить фильтры» очищает **расширенные фильтры**, но не меняет верхний период. На общей странице шахматные и шашечные мини-сводки по-прежнему не зависят от расширенных фильтров, **но зависят от верхнего периода**, чтобы вся страница показывала согласованный интервал. На страницах отдельных игр и сводки, и графики используют локальные фильтры.

Исторические three_check остаются **только в общей статистике** и её графике; в шахматном разделе и шахматной мини-сводке учитывается исключительно chess/standard. Число партий в графике суммируется по count, без изменения CSV или логики загрузки.

## Схема `games.csv`

Кодировка UTF-8, разделитель — запятая, первая строка — заголовки. Каждая строка CSV соответствует одной исходной записи в ячейке одного победителя. Множитель сохраняется в `count`; общая статистика считается через сумму `count`, а не число строк. Запятые и кавычки в текстовых полях требуют стандартного CSV-экранирования.

| Поле | Значение |
| --- | --- |
| `id` | Стабильный уникальный ID, например `G040`; не перенумеровывать после первой публикации. |
| `date` | ISO-дата `YYYY-MM-DD`. Укороченные даты наследуют месяц/год из предыдущей строки Google Docs. |
| `game` | `checkers`, `chess`, `quoridouble`, `hexagon`. По умолчанию в Google Docs — шашки. |
| `variant` | Для шашек: `breakthrough` (по умолчанию), `standard` (`std`) или `antidraughts` (`ant`, `🐜`, поддавки). Для шахмат: `three_check` или `standard`. Для остальных: `default`. |
| `checkers_type` | **Независимо от варианта:** `international` (по умолчанию) или `russian` (префикс `r_`/`R_`). Для нешашечных игр — пусто. |
| `winner` | `lekha`, `papa` или `draw`. Победителя определяет колонка источника «Леха»/«Папа»; ничьих в нынешней истории нет. |
| `clock_type` | `bd`, `hg`, `sd`, `sdel`, `nt` или пусто. `nt` — *без таймера*: также значение по умолчанию, когда в записи нет контроля времени. Для Quoridouble/Hexagon всегда `nt`. Все `bd`/`hg`/`sd`/`sdel` относятся к шашкам. Для обычных шахмат с `5+5`/`3+2` тип в CSV остаётся пустым, а контроль хранится в `time_control_raw`: по правилу источника это **инкремент Фишера**. Для шашек пустой тип с `time_control_raw` по-прежнему означает неизвестную систему часов. Старые `three_check` без часов — `nt`. |
| `base_seconds` | Неотрицательное целое: начальное время в секундах (ноль разрешён для `bd` и `sdel` с положительной задержкой) для `bd`/`hg`/`sd`/`sdel`. При `nt` или пустом `clock_type` пусто. |
| `delay_seconds` | Целое неотрицательное число для `bd` и `sdel`. Для других типов и `nt` — пусто. Это задержка, а не инкремент Фишера. Для шахмат `5+5`/`3+2` поле не используется: значение инкремента остаётся в `time_control_raw`. |
| `side_mark` | Буквальный суффикс `w`, `b`, `wb`, а также буквальные `ч`/`б` для шахмат, или пусто. До уточнения не объединять разные алфавиты и не выводить личность игрока из цвета. `wb` не делится на отдельных игроков. |
| `papa_drunk` | `true` при наличии пометки `п`, иначе `false`. Отсутствие отметки не доказывает обратного. |
| `ending` | `time` при пометке `t` (время истекло); пусто — способ завершения не указан. Не путать с `clock_type`. |
| `count` | Положительное целое; `3*sdel...` или `3 sdel...` означает три результата с теми же параметрами. |
| `source_entry` | Точный текст исходной записи Google Docs, чтобы проверить миграцию. Публичное поле. |
| `notes` | Дополнительное публичное примечание; пусто, если отсутствует. |
| `time_control_raw` | Буквальная запись `N+N`. В шашках — если система часов не названа (`0+20`); в обычных шахматах — для стандартного инкремента Фишера (`5+5`, `3+2`; минуты + секунды на ход). Для явно названных шашечных систем поле пустое. |

Физический порядок полей в CSV: `id,date,game,variant,winner,clock_type,base_seconds,delay_seconds,side_mark,papa_drunk,count,source_entry,notes,checkers_type,ending,time_control_raw`. Новое поле добавлено в конец для сохранения прежнего порядка. Два новых поля добавлены в конец, чтобы сохранить прежние поля и их порядок.

### Правила чтения сокращений

| Запись в Google Docs | Нормализация |
| --- | --- |
| Отсутствует название игры | `game=checkers` |
| Отсутствует вариант шашек | `variant=breakthrough` |
| `ant` / `🐜` | `game=checkers`, `variant=antidraughts` (поддавки) |
| `std` | `variant=standard` для шашек |
| Отсутствует тип шашек | `checkers_type=international` |
| `r_` или `R_` | `checkers_type=russian`, независимо от `variant` |
| `bd1/2+1` | Bronstein: `bd,30,1` (секунды) |
| `hg3` | Hourglass: `hg,180,` |
| `sd 2` | Sudden Death: `sd,120,` |
| `sdel 3/4+1` | Simple Delay: `sdel,45,1` |
| `nt` или отсутствие контроля времени | `clock_type=nt`, оба числовых поля пустые. Это также значение по умолчанию для шахмат без указанного таймера. |
| `bd 0+20`, `bd 0+15` | Bronstein: 0 начальных секунд, задержка соответственно 20 или 15 секунд (положительная задержка обязательна) |
| `sdel 0+15`, `sdel 0+20`, `R_sdel 0+15` | Simple Delay: 0 начальных секунд, задержка 15 или 20 секунд; `R_` означает русские шашки. При нулевой базе задержка должна быть положительной, как и для `bd`. |
| `Шх 5+5`, `Шх 3+2` | Обычные шахматы с **инкрементом Фишера**, соответственно 5 минут + 5 секунд/ход и 3 минуты + 2 секунды/ход. `time_control_raw=5+5` / `3+2`, `clock_type`, `base_seconds` и `delay_seconds` пусты (без изменения CSV-схемы). |
| `🐜 0+20` без `bd` | Поддавки; `time_control_raw=0+20`, тип часов остаётся неизвестным |
| `ч`, `б` в шахматах | Сохранять буквальные пометки в `side_mark` (не подменять английскими `w`/`b` без правила источника) |
| Другие игры: `Шх3ш`, `hx`, `Qd`/`Quoridouble`/`Quoribouble` | Для старых партий без контроля времени — `clock_type=nt`. Новые шахматы могут иметь буквальный `time_control_raw` при неуказанной системе часов. |
| `Шх3ш` | `chess,three_check` |
| `hx` | `hexagon,default` |
| `Qd`, `Quoridouble`, `Quoribouble` | `quoridouble,default` (опечатка в названии не создаёт другую игру) |
| `w`, `b`, `wb` | Значение `side_mark` без додумывания, кто за какой цвет играл |
| `t` | `ending=time`: окончание по времени; не меняет победителя |
| `п` | `papa_drunk=true` |
| `2*` или `2 ` в начале записи | `count=2` |

Маркеры могут сочетаться: `sdel 1+2 tп` — международные шашки «Прорыв», Simple Delay 60+2 секунды, победитель из колонки, `ending=time`, `papa_drunk=true`. `std nt п` — классические международные шашки, без таймера, с пометкой `п`. Для пустого поля в CSV оставляют два соседних разделителя.

### Группировка в блоке «Таймеры и контроль времени»

Блок строится по **текущим фильтрам** из `games.csv` с учётом `count`. Порядок и названия категорий фиксированы в `renderClocks()` файла `index.html`:

- **«Все игры без таймера»** — все записи с `clock_type=nt` независимо от `game`, включая шашки, шахматы «Три шаха», Quoridouble и Hexagon.
- **«Шашки без таймера»** — только записи с `clock_type=nt` и `game=checkers`; **это подмножество предыдущей строки, а не дополнительные партии**. Две строки нельзя суммировать между собой.
- Остальные режимы получают явный префикс игры: **«Шашки · »** или **«Шахматы · »**. Известные часы группируются по системе и параметрам; у шахмат `time_control_raw` отображается как инкремент, а у шашек с неуказанной системой — буквально. Например: «Шашки · Bronstein · 0:00 + 20 с» и «Шахматы · Инкремент Фишера · 5+5».
- Каждая строка показывает `Всего`, `Лёха`, `Папа` и при наличии `Ничьи`; цветная полоса отражает доли побед внутри строки. Категории строятся заново при изменении фильтров, пустые группы не отображаются. Записи с пустым `clock_type`, но заполненным `time_control_raw`, попадают в этот блок отдельными группами. Если оба поля пустые, запись не попадает в блок; для шахмат без времени следует сохранять `clock_type=nt`. Фильтр «Инкремент (Фишер)» включает шахматные `N+N`, а «Не указана» относится к шашкам с неизвестной системой.

Контрольный пример для статистики на 21.10.2026 без фильтров: «Все игры без таймера» — **31** (Лёха 14, папа 17), из них «Шашки без таймера» — **9** (Лёха 6, папа 3), остальные игры без таймера — **22**. Не менять `games.csv` ради группировки: это исключительно представление на дашборде.

## GitHub update policy

Repository-scoped agent guidance is in [`AGENTS.md`](AGENTS.md). Routine, fully verified CSV updates under `game-stats/` go **directly to `main` in one commit without a Pull Request**. For schema, deployment or substantial dashboard changes, use a branch and Pull Request, validate it, then **merge it yourself after successful checks** when the change is approved in the user's request. Do not require the user to click Merge. Never apply these rules to other repositories or directories.
