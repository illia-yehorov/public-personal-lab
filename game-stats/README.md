# Рубилово — статистика игр

Простой локальный дашборд для результатов Лёхи и папы. Нужны только `index.html` и `games.csv`: нет базы данных, Python, сервера приложения и внешних JS-библиотек.

## Как открыть

1. Скачай папку `game-stats` (или клонируй репозиторий), сохрани `index.html` и `games.csv` рядом.
2. Открой `index.html` двойным щелчком. Нажми **«Загрузить CSV»** и выбери `games.csv`. Браузеры обычно запрещают локальному HTML автоматически читать соседние файлы через `file://`.
3. Если открыть страницу через HTTP(S), она автоматически загружает соседний `games.csv` при открытии / обновлении (запрос без кеша). Например, из корня репозитория: `python -m http.server 8000`, затем `http://localhost:8000/game-stats/`. Python здесь **не обязателен**: это только пример локального статического веб-сервера.
4. После изменения CSV: при HTTP(S) обнови страницу или нажми **«Обновить»**; при локальном `file://` повторно выбери файл кнопкой **«Загрузить CSV»**. HTML пересчитывает все карточки, графики и таблицу из загруженных данных. Сам HTML переделывать не нужно.

**Важно:** текущая страница показывает статистику и фильтрует её, но **не редактирует и не перезаписывает CSV**. Вносить новые результаты следует непосредственно в `games.csv` (UTF-8) через текстовый редактор или Excel. Не открывай приватный репозиторий или файл публично, если не хочешь делиться личными пометками.

## Формат `games.csv`

UTF-8, первая строка — названия полей, разделитель — запятая `,`, одна строка — **одна исходная запись**. Для пакета одинаковых результатов используй `count`: дашборд считает именно сумму `count`, а не количество строк. Поля в кавычках при наличии запятых оформляются по обычным CSV-правилам: `"текст, с запятой"`; кавычка внутри поля удваивается `""`.

| Поле | Обязательно | Формат / смысл |
| --- | --- | --- |
| `id` | да | Уникальный идентификатор строки, например `G040`. После записи не переиспользуй. |
| `date` | да | Дата `YYYY-MM-DD` (например, `2026-10-09`). |
| `game` | да | `checkers`, `chess`, `quoridouble`, `hexagon`. |
| `variant` | да | Для `checkers`: `international` или `russian`; для `chess`: `three_check` или `standard`; для остальных: `default`. |
| `winner` | да | `lekha`, `papa` или `draw` (ничья). Колонка Word «Леха»/«Папа» определяет победителя. |
| `clock_type` | нет | `bd`, `hg`, `sd`, `sdel`; **пусто**, если тип часов в источнике не указан (это не утверждение, что игра была без часов). |
| `base_seconds` | если есть `clock_type` | Начальное время **в секундах**, положительное целое (`1` мин = `60`, `1/2` мин = `30`). Иначе пусто. |
| `delay_seconds` | для `bd` и `sdel` | Величина задержки в секундах (`0` допустим). Для `hg`, `sd` и неизвестных часов — пусто. Это **не Fischer increment**. |
| `side_mark` | нет | Буквальная отметка из источника: `w`, `b`, `wb` или пусто. `wb` сохраняется как есть; не выводим из неё цвет отдельного игрока. |
| `papa_drunk` | да | `true`, если у записи есть суффикс `п`; `false` — суффикса нет. Отсутствие отметки не доказывает обратного. |
| `count` | да | Положительное целое: `3*sdel...` = `3`; без множителя = `1`. |
| `source_entry` | нет | Оригинальная запись из Word для проверки переноса, например `3 sdel 2+1w`. Для новых строк можно оставить пустым. |
| `notes` | нет | Дополнительное примечание (свободный текст). |

### Расшифровка старой записи

- Без префикса `r_` запись с таймером означает **международные шашки**. `r_` — **русские шашки**.
- `bd` — Bronstein Delay; `hg` — Hourglass; `sd` — Sudden Death; `sdel` — Simple Delay. Например, `bd1/2+1` → `bd,30,1`; `hg3` → `hg,180,`.
- `Шх3ш` → `chess,three_check`; `hx` → `hexagon,default`.
- `Qd`, `Quoridouble`, `Quoribouble` → **одна игра**, правильное нормализованное имя `quoridouble`.
- `w`, `b`, `wb` сохраняются в `side_mark`, `п` — в `papa_drunk`. Таймер и сторона, не указанные в источнике, остаются пустыми.
- `2*`, `2 `, `3*`, `3 ` перед названием — число одинаковых результатов, сохраняется в `count`. Исходная запись также остаётся в `source_entry`.

### Пример новых записей

```csv
id,date,game,variant,winner,clock_type,base_seconds,delay_seconds,side_mark,papa_drunk,count,source_entry,notes
G040,2026-10-11,checkers,international,lekha,sdel,60,2,b,false,1,,
G041,2026-10-11,chess,three_check,papa,,,,w,false,1,,
G042,2026-10-11,quoridouble,default,draw,,,,,false,1,,
```

Для новых партий рекомендуется `count=1` и отдельная строка на каждую партию. В старых пакетах (`count>1`) можно точно посчитать победы и количество партий, но **нельзя восстановить точный порядок партий или серии побед в течение дня**. В документе дата `28.09.2026` задаёт год для остальных строк; пустая дата `10.10` не создаёт партию.

Проверка: фильтры меняют все показатели, но не исходный CSV. Таблица показывает исходную запись, а сумма результатов должна всегда равняться количеству партий в текущей выборке.

## Редактирование CSV

Если правишь CSV вручную, сохраняй заголовки, уникальный `id` и пустые значения как пустые поля между запятыми. Страница сообщит об ошибке, если обнаружит неправильную структуру CSV.
